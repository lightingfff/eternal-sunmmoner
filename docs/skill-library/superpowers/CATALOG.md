# All 15 Superpowers skills

All main texts below were read at pinned version 7.0.2. Their local support files
are retained verbatim under each directory; selected support-source inspection is
described separately in [READING_NOTES](READING_NOTES.md). This catalog records
what each teaches and when it fits this game, not permission to invoke every skill.

| Main source | What it teaches | ETERNAL SUMMONER application |
|---|---|---|
| [using-superpowers](upstream/skills/using-superpowers/SKILL.md) | Discover applicable skills, prioritize process guidance, map tools to the actual harness. | Reference entrypoint only; use project routing rather than the automatic 1% invocation rule. No global config changes. |
| [brainstorming](upstream/skills/brainstorming/SKILL.md) | Read existing context before asking; establish intent, alternatives, boundaries and acceptance; use a short or full design. | Clarify consequential open gameplay choices; preserve decisions already approved in the conversation/issues. Visual companion is optional and inactive. |
| [writing-plans](upstream/skills/writing-plans/SKILL.md) | Decide exact files/interfaces, size tasks around reviewable behavior, specify tests/commands and scan uncovered failure modes. | Plans for combat/save/render integration include task ownership, camera/Android constraints and measurable acceptance; no ceremonial reapproval of settled work. |
| [executing-plans](upstream/skills/executing-plans/SKILL.md) | Implement inline with a task ledger, persistent decisions, verification and final review. | Root can integrate coupled renderer changes serially and resume after compaction. Retain evidence; project exact-SHA re-review still applies. |
| [subagent-driven-development](upstream/skills/subagent-driven-development/SKILL.md) | Fresh scoped implementation/review contexts, briefs, BASE ranges, report contracts, fix loops and whole-branch review. | Only for actual authorized native delegation; one writer per file. The upstream five-round escalation and model defaults do not replace project limits/tools. |
| [dispatching-parallel-agents](upstream/skills/dispatching-parallel-agents/SKILL.md) | Split independent failure domains; give each a self-contained scope, constraints and expected report. | Independent read-only audits or explicitly disjoint asset tasks. Related failures/shared runtime files remain serialized. |
| [systematic-debugging](upstream/skills/systematic-debugging/SKILL.md) | Reproduce, inspect recent changes and boundary evidence, compare working cases, test one hypothesis, fix root cause. | Separate APK compile/signing/install problems from artifact retrieval; inspect input ownership or renderer state before changing symptoms. Keep diagnostics free of secrets. |
| [test-driven-development](upstream/skills/test-driven-development/SKILL.md) | Observe a meaningful failing behavior test, implement minimally, verify green and refactor; test the real system rather than mock call counts. | Regression tests for duplicate hits, save transactions, input and retry. Scope checks to risk; do not delete prior work or manufacture tests for trivial prose edits. |
| [verification-before-completion](upstream/skills/verification-before-completion/SKILL.md) | Run the command that proves the claim, read complete result/exit status and disclose gaps. | Build/test/CI on the reported HEAD, inspect actual PNGs/APK hashes; distinguish native host captures from physical phone metrics. |
| [requesting-code-review](upstream/skills/requesting-code-review/SKILL.md) | Supply requirements, BASE/HEAD and a precise review package; resolve significant findings. | Independent code/creative/QA review on the same SHA; a GitHub request is not evidence an external agent actually ran. |
| [receiving-code-review](upstream/skills/receiving-code-review/SKILL.md) | Understand feedback, verify it against the codebase, respond technically and fix one item at a time; push back with evidence when appropriate. | Reply to each finding, assign a single corrective writer and request re-review after new commits. No automatic agreement or silent dismissal. |
| [using-git-worktrees](upstream/skills/using-git-worktrees/SKILL.md) | Detect existing isolation/submodules before creating worktrees; preserve native host ownership and clean baselines. | Inspect actual workspace/branch, preserve dirty gameplay work and use the existing isolated branch or an authorized separate task worktree. No automatic dependency install. |
| [finishing-a-development-branch](upstream/skills/finishing-a-development-branch/SKILL.md) | Verify work, determine base, offer integration choices and preserve PR workspaces. | Use the already authorized review-PR path. The merge/discard examples do not authorize main writes, force push or cleanup; user alone merges. |
| [writing-skills](upstream/skills/writing-skills/SKILL.md) | Keep skill descriptions discoverable; use retrieval/application/pressure evaluation to validate behavioral guidance. | Maintain a narrow reference adapter and honest coverage. Hash/link checks are not evidence of an upstream RED/GREEN behavioral eval or automatic activation. |
| [diagnosing-superpowers](upstream/skills/diagnosing-superpowers/SKILL.md) | Scope an observed session problem; cite transcript path/line evidence; protect read-only originals and explicitly approved exports. | Conditional reference for a separately requested session diagnosis. No transcript sweep, global diagnostic directories, bundle/export or upstream report in this task. |
